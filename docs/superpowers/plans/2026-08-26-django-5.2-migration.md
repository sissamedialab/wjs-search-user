# wjs-search-user Django 5.2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the `wjs.user_search` package work correctly under Django 5.2, with code-level verification now and live/functional verification explicitly deferred until `wjs-submission-project` and `wjs-profile-project` are also ported.

**Architecture:** No structural changes — a compatibility pass over 7 non-trivial `.py` files. No live verification is possible standalone: `apps.py.ready()` imports `urls.py` → `views.py`, which has module-level imports on `plugins.wjs_submission.models.Collaboration` and `wjs.jcom_profile.models.Correspondence` — neither portable yet.

**Tech Stack:** Python 3.11+, Django 5.2, `django-upgrade`, `ruff`.

**Spec:** `docs/superpowers/specs/2026-08-26-django-5.2-migration-design.md` (this repo).

## Global Constraints

- Python floor: `>= 3.11` (confirmed for all five `wjs-*` repos in this migration effort).
- Django target: `5.2`.
- No behavioral change.
- No `install_requires` changes — cross-plugin imports stay undeclared, per Janeway's plugin
  architecture (path injection, not pip).
- No automated test suite exists or is added (`tests.py` is an unused stub).
- Package version bumps to `2.1.0` so `wjs-submission-project`'s `wjs-user-search >= 2.0.3` pin
  remains satisfiable.
- This repo has **no lint/pre-commit config at all** (no `pyproject.toml`, no
  `.pre-commit-config.yaml`) — there is no local lint job to run as part of verification.

### Task 1: Confirm no Django 5.2 code incompatibilities exist

**Files:**
- Verify (no modifications expected): `wjs/user_search/admin.py`, `apps.py`, `forms.py`,
  `urls.py`, `views.py`, `widgets.py`

**Interfaces:** None — this task produces no new code.

- [ ] **Step 1: Run `django-upgrade` over the 6 non-empty files**

```bash
django-upgrade --target-version 5.2 \
  wjs/user_search/admin.py wjs/user_search/apps.py wjs/user_search/forms.py \
  wjs/user_search/urls.py wjs/user_search/views.py wjs/user_search/widgets.py
git diff --stat
```

Expected: exit code `0`, empty `git diff` — confirmed when this plan was written. If a diff now
appears, review and apply it, then re-run until empty or intentionally kept.

- [ ] **Step 2: Run `ruff check` and note pre-existing findings are out of scope**

```bash
ruff check wjs/user_search/admin.py wjs/user_search/apps.py wjs/user_search/forms.py \
  wjs/user_search/urls.py wjs/user_search/views.py wjs/user_search/widgets.py
```

Expected: 17 findings, all pre-existing style/quality issues unrelated to Django 5.2 — confirmed
when this plan was written: `F401` unused imports (`admin.py`'s unused `admin` import, `apps.py`'s
unused `urls` import — note `apps.py`'s import is a deliberate registration side-effect via
`ready()`, not truly dead code, so leave it despite the `F401` flag), `I001` import-sort ordering
(`forms.py`, `urls.py`, `views.py`), 12× `C408` (`dict()` calls that could be literals), and one
`RUF012` (`widgets.py`'s `Media.css = dict(...)`). **Do not fix these** — they're pre-existing
code-quality nits, out of this port's scope (matches the "no scope creep" approach used for
`wjs-themes`' pre-existing `noqa`-style findings). If `ruff check` reports anything *else* (a new
category not in this list), investigate before proceeding.

- [ ] **Step 3: Manually confirm the APIs each file uses are valid in Django 5.2**

- `admin.py`: only `from django.contrib import admin`, nothing registered — no API surface to
  break.
- `apps.py`: `django.apps.AppConfig`, `ready()` importing `.urls` — current API.
- `forms.py`: `django.forms.Form`/`CharField` — current.
- `widgets.py`: `django.forms.widgets.Input`, `Media` inner class, `use_required_attribute` — all
  current; unaffected by Django 5.0's div-based default form-renderer change (this widget defines
  its own `template_name`, not relying on the default).
- `urls.py`: `django.urls.re_path` (imported `as url`) — the modern API, not the removed
  `django.conf.urls.url`.
- `views.py`: `django.http.HttpResponse`, `django.shortcuts.render`,
  `django.views.generic.FormView`/`View` — all current; `Account.objects.raw()` /
  `Collaboration.objects.raw()` raw-SQL usage is unaffected by any Django 5.x change.

Expected outcome: no code changes identified.

- [ ] **Step 4: Record the finding — no commit needed**

Since Steps 1–3 produced no file changes, there is nothing to commit for this task. Note in your
task-tracking that Task 1 found zero Django-5.2 code incompatibilities.

### Task 2: Update `setup.cfg` — version bump, Python floor

**Files:**
- Modify: `setup.cfg`

**Interfaces:** Produces `wjs.user_search` version `2.1.0`, which `wjs-submission-project`'s
`wjs-user-search >= 2.0.3` pin (unaffected, still satisfied) references as "the Django-5.2-compatible
release."

- [ ] **Step 1: Bump the version**

Current (`setup.cfg` line 3):

```ini
version = 2.0.4.dev1
```

Change to:

```ini
version = 2.1.0
```

- [ ] **Step 2: Drop the stale Python 3.9 classifier and add `python_requires`**

Current (`setup.cfg`, `[metadata]` classifiers and `[options]`):

```ini
classifiers =
    Environment :: Web Environment
    Framework :: Django
    Intended Audience :: Developers
    License :: OSI Approved :: AGPL License
    Operating System :: OS Independent
    Programming Language :: Python
    Programming Language :: Python :: 3
    Programming Language :: Python :: 3 :: Only
    Programming Language :: Python :: 3.9
    Topic :: Internet :: WWW/HTTP
    Topic :: Internet :: WWW/HTTP :: Dynamic Content

[options]
include_package_data = true
packages = find_namespace:
```

Change to:

```ini
classifiers =
    Environment :: Web Environment
    Framework :: Django
    Intended Audience :: Developers
    License :: OSI Approved :: AGPL License
    Operating System :: OS Independent
    Programming Language :: Python
    Programming Language :: Python :: 3
    Programming Language :: Python :: 3 :: Only
    Topic :: Internet :: WWW/HTTP
    Topic :: Internet :: WWW/HTTP :: Dynamic Content

[options]
include_package_data = true
packages = find_namespace:
python_requires = >= 3.11
```

- [ ] **Step 3: Verify the edit**

```bash
python -c "
import configparser
c = configparser.ConfigParser()
c.read('setup.cfg')
assert c['metadata']['version'] == '2.1.0'
assert c['options']['python_requires'].strip() == '>= 3.11'
assert '3.9' not in c['metadata']['classifiers']
print('OK')
"
```

Expected: `OK`.

- [ ] **Step 4: Commit**

```bash
git add setup.cfg
git commit -m "build: bump to 2.1.0, add python_requires >=3.11

Version bump lets wjs-submission-project's wjs-user-search >=2.0.3
pin resolve to a known Django-5.2-compatible release.
python_requires >=3.11 matches the confirmed floor for all five wjs-*
repos in this migration effort; drops the stale Python 3.9 classifier."
```
